
# AWS Project Screenshots

This directory contains screenshots and visual evidence collected during the implementation and testing of the Enterprise AWS Cloud Infrastructure project.

## Purpose

The screenshots provide evidence of actual AWS resource configurations, deployment activities, connectivity tests, and infrastructure validation.

## Screenshot Categories

### 1. VPC and Networking
- VPC configuration
- Public and private subnet details
- Internet Gateway
- NAT Gateway
- Route table associations

### 2. EC2 and Compute
- Bastion Host instance
- Private application server A
- Private application server B
- EC2 instance status checks
- Apache service verification

### 3. Load Balancing
- Application Load Balancer configuration
- Listener configuration
- Target Group configuration
- Healthy registered targets
- Application access through ALB

### 4. Auto Scaling
- Launch Template configuration
- Auto Scaling Group settings
- Instance launch activity
- Scaling verification

### 5. Database and Storage
- RDS MySQL configuration
- EBS volume configuration
- EFS file system and mount verification
- S3 bucket configuration

### 6. Monitoring and Auditing
- CloudWatch dashboards
- CloudWatch alarms
- CloudTrail event history

## Screenshot Documentation Standards

Each screenshot should:

- Show the relevant AWS service or test result.
- Include a descriptive filename.
- Avoid exposing credentials, private keys, passwords, or sensitive information.
- Be accompanied by a short explanation where necessary.
- Represent an actual configuration or verified test result.

## Naming Convention

Use descriptive filenames, for example:

- vpc-configuration.png
- public-private-subnets.png
- ec2-instance-status.png
- alb-target-health.png
- apache-server-verification.png
- autoscaling-group.png

## Important Note

Only genuine screenshots from the actual project implementation will be uploaded.

Illustrative images and unverified configurations will not be presented as implementation evidence.

## Project Status

Screenshots will be added progressively as each AWS component is implemented and verified.
